# Backend — decisions & open placeholders

Written during an autonomous session building the Milestone 2 backend foundation
(data model + pure domain logic + tests). This records **what I decided without
you** and **what I deliberately left as a placeholder** so we can review together.
Nothing here is locked — flag anything you disagree with.

## ⚠️ Architecture override (2026-07-22) — Redis + BullMQ reinstated

Ahmad **overrode** `AGENT_GUIDE.md` §2's locked "no Redis / no BullMQ in v1" decision.
The stack now runs a **Redis** container and a dedicated **worker** process; heavy/background
work (image processing, expiry sweep, analytics flush, email) is dispatched through **BullMQ**
queues instead of inline processing + cron. The guide has an override note pointing here.

Rationale accepted by Ahmad over the "not-over-complicated" concern: he wants proper async job
handling from the start. Job logic is still written behind a small queue abstraction
(`src/lib/jobs`) so queues stay easy to read and test.

## Decisions I made (please confirm)

1. **Prisma 7, new engine-free client.** Prisma 7 dropped `url` from the schema
   and requires a driver adapter. Client generates to `src/generated/prisma`
   (gitignored; regenerated by `postinstall` / `pnpm db:generate`). Runtime uses
   `@prisma/adapter-pg` + `pg`.
2. **Domain logic is decoupled from Prisma.** `src/server/*` uses plain TS types
   (`src/server/types.ts`) that mirror the Prisma enums, so tests are hermetic
   (no DB, no generated client). Enums must be kept in sync by hand.
3. **Publish gating = `active` only.** AGENT_GUIDE §8 says "no active
   subscription → no publish." I read that strictly: a site in **grace** can
   still be *served* (`isSiteLive`) but **cannot push new publishes**
   (`canPublishWithSubscription`). ⚠️ If you'd rather allow publishing during
   grace, it's a one-line change in `billing.ts`.
4. **`grace` is billing-derived, not a stored `Site.status`.** `Site.status` is
   `draft|published|suspended` (matches the guide). `grace` lives on
   `Subscription.status` and is computed from expiry. (Same reconciliation noted
   in the design brief.)
5. **`commission_pct` is a percentage 0–100** (not a 0–1 fraction).
   `computeCommission` rounds to 2 decimals. Confirm the rounding rule for SYP
   (whole pounds?).
6. **Payment extends by whole years, stacking.** Paying while still active adds a
   year onto current expiry; paying after lapse extends from now. Feb-29 clamps
   to Feb-28.
7. **Section library frozen at 13 types** with per-page-type allow-lists
   (`sections.ts`). The allow-lists (which sections each page type permits) are
   my sensible defaults — **please sanity-check them**, especially `about` /
   `contact` / `services`.
8. **Opening hours: no overnight spans in v1** (close must be after open, same
   day). Revisit if a business closes after midnight.
9. **Renewal alerts at T-14 and T-3**, most-urgent-wins. Uses `Math.ceil` on days
   remaining (entering the 14-day window fires at day 14).

## Placeholders — need your input before implementing

- **Better Auth (`src/lib/auth.ts`) is a stub.** It throws until wired. Open
  questions live in that file's header: email transport (verify/reset),
  organization plugin vs. our Workspace tables, User-table ownership, and how
  `role`/`workspaceId`/`siteAccess[]` land on the session as `SessionClaims`
  (the shape `src/server/access.ts` already consumes). This is the main blocker
  for real API routes.
- **The provisional `User` model** in the schema matches Better Auth conventions
  but will be reconciled when Better Auth's CLI generates its auth tables
  (Session/Account/Verification are not modeled yet).

## Explicitly NOT done this session (next steps)

- **No migration run yet.** The schema validates and the client generates, but
  `prisma migrate` needs a reachable DB. To run it, uncomment `5432:5432` in
  `compose.yaml`, point `DATABASE_URL` at `localhost:5432`, then
  `pnpm db:migrate --name init`.
- **No Route Handlers / Server Actions.** They depend on auth + session, which is
  the placeholder above. Deferred intentionally (also want to read the Next 16
  docs per AGENTS.md before writing framework code).
- **No server-side services that touch the DB** (create-site, publish, record-
  payment). The *pure* pieces of that logic exist and are tested; the DB-writing
  wrappers come once auth + migrations are in.
- **Dockerfile doesn't run `prisma generate` yet.** There's a comment marking
  where to add it in the builder stage before we containerize DB-backed code.
